# Publicação no GitHub

[Voltar ao projeto](README.md)

## Pasta de entrega

O README é a página inicial. Artigo, roteiros, prevenção e capturas estão vinculados por caminhos relativos. Não é necessário executar nenhum teste para publicar a documentação.

## Publicar pela interface

1. Crie um repositório público no GitHub. Sugestão: **Lynfort-brute-force-lab**.
2. Descrição sugerida: **Laboratório educacional Lynfort com Kali Linux e Medusa: FTP, DVWA e password spraying em SMB, com artigo, evidências e validação manual.**
3. Use **Add file → Upload files** e arraste o conteúdo desta pasta, preservando as subpastas. `assets` deve ficar no mesmo nível de `README.md`.
4. Confira a prévia do README, os links e as imagens.
5. Confirme o envio e copie o endereço do repositório para a entrega da DIO.

Publique os arquivos extraídos, em vez de apenas um ZIP. O GitHub renderiza o Markdown diretamente.

## Material selecionado

As capturas foram copiadas sem alteração dos pixels. A numeração tem lacunas. Alguns nomes foram normalizados; a origem de cada imagem está em [Evidências](docs/evidencias.md).

As quatro listas foram reconstruídas das entradas visíveis. Não são cópias dos arquivos originais do Kali. Não há logs fabricados nem histórico Git incluído.

O rascunho Word e as imagens de diagnóstico ficaram fora da entrega pública. O artigo preserva os temas da tese e revisa imprecisões com referências.

## Conferência final

As capturas selecionadas não mostram um valor literal de `PHPSESSID`. O comando web mostra apenas a variável. Os IPs são privados; as senhas são padrões conhecidos ou valores fictícios usados deliberadamente no laboratório.

Nomes de usuário locais, MAC e datas aparecem nas capturas originais. Victor Godoy e BR-Godooy são a autoria do portfólio.

A análise de prevenção é documental. Não foi executado um scan automatizado do ambiente nem reteste após aplicação de defesas.
